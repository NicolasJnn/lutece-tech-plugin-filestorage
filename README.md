# Plugin filestorage

## Introduction

This plugin lets a Lutece 8 site publish its own files without any manual deposit on its servers. Files are uploaded and managed from the back office, and their links are inserted into contents from the editor. The files themselves are kept by a file store service provider of the core, chosen by configuration : blobstore by default.

Main features :

* upload of files from the back office, restricted by type and size
* management table : search by title, modification of the title and the description, replacement of the content, removal, copy of the link
* separate permissions to create, modify and remove files (RBAC)
* insertion of a link to a file into any content, through the insert services of the editor
* storage delegated to any file store service provider : blobstore by default, the database provider of the core, or another one

## Back office

The feature **File storage** (right `FILESTORAGE_MANAGEMENT`, level 1) gives access to the management table.

The actions on the files are granted through the RBAC resource type `FILESTORAGE_FILE` and its permissions `CREATE`, `MODIFY` and `DELETE`. The role `filestorage_manager` grants all of them.

The insert service **Stored file** is offered by the insert service selector of the core. Using it requires the right `FILESTORAGE_INSERT` (level 3), in addition to the right of the core that opens the selector.

## Security

* the type of an uploaded file is checked three times : its extension, its declared MIME type and the signature of its content
* the stored name of a file is cleaned, and its stored MIME type is the verified one
* every action is protected against cross-site request forgery
* files are served by the download servlets of the core, always as attachments, through encrypted links

## Configuration

The properties are defined in `WEB-INF/conf/plugins/filestorage.properties`. Each of them can be overridden by an environment variable : the key in upper case, dots replaced by underscores (for example `FILESTORAGE_ALLOWEDTYPES`).

| Property | Default | Description |
|---|---|---|
| `filestorage.fileStoreServiceProvider` | `blobstore.blobStoreFileService` | name of the file store service provider that keeps the files |
| `filestorage.allowedTypes` | `pdf,jpeg,png` | allowed types ; html is supported too, a type without a known signature is only checked on its extension |
| `filestorage.maxFileSize` | `15728640` | maximum size, in bytes |
| `filestorage.storedFile.itemsPerPage` | `50` | rows per page of the management table |

## Storage

By default the files are kept by the blobstore plugin (`blobstore.blobStoreFileService`), on disk under the directory `blobstore.file.system.path` (environment variable `BLOBSTORE_FILE_SYSTEM_PATH`, `/var/blobs/` by default). In a container, this directory must be a persistent volume, writable by the user running the application server, shared in read-write mode between replicas and included in the backups.

To keep the files elsewhere, set `filestorage.fileStoreServiceProvider` to the name of another file store service provider, for example `defaultDatabaseFileStoreProvider` to keep them in the database of the core. The plugin uses the links and the access control of that provider : the validity of the links is the one of its download service (`lutece.file.download.validity` for the download service of the core, 0 meaning no expiry).

## Installation

Add the dependency to the pom of the site :

```xml
<dependency>
    <groupId>fr.paris.lutece.plugins</groupId>
    <artifactId>plugin-filestorage</artifactId>
    <type>lutece-plugin</type>
</dependency>
```

The plugin depends on `plugin-blobstore`. The SQL scripts of the plugin create the table `filestorage_file`, the rights and the role. The site declares both plugins installed with the keys `core.plugins.status.filestorage.installed`, `core.plugins.status.filestorage.pool`, `core.plugins.status.blobstore.installed` and `core.plugins.status.blobstore.pool`.

## Limits

* replacing the content of a file changes its link : the links already inserted in contents no longer work
* files are always downloaded, never displayed in the browser ; HTML pages are better managed with the htmlpage plugin
* no dedicated button in the editor : the insertion goes through the insert service selector of the core
